TASK: TASK-002
# Plan

## Özet
Mevcut durum (TASK-001): backend'de sadece `POST /api/embeddings` var (`embedding` feature: `EmbeddingController`, `EmbeddingService`, `EmbeddingClient`/`OllamaEmbeddingClient`, `EmbeddingProperties(baseUrl, model, connectTimeout, readTimeout)`), `exception` paketinde `BaseException`, `ServiceUnavailableException`, `GlobalExceptionHandler`; `config` paketinde `ClockConfig`, `OpenApiConfig`. Veritabanı, Docker ve `deployment/` dosyası yok.

Yeni durum:
1. PostgreSQL 18 + pgvector (Docker, `pgvector/pgvector:0.8.1-pg18`) + Flyway şeması: `workspaces`, `sources`, `chunks`, `ingestion_jobs`, `search_events`. Java tarafı Spring Data JPA + Hibernate 7 entity'leri (`Workspace`, `Source`, `Chunk`, `IngestionJob`, `SearchEvent`; vektör kolonu `hibernate-vector` ile `float[]` ↔ `vector(1024)`); PostgreSQL'e özgü sorgular (set_config, EXPLAIN, FTS, vektör/hybrid CTE, `nextval`) repository'lerde `@Query(nativeQuery = true)` + projection (D1). Projede `JdbcClient`/`JdbcTemplate` yok (Düzeltme turu 1).
2. Dosya yükleme (PDF, TXT/MD, CSV) → 202 + arka planda içe alma işi: `QUEUED → PARSING → CHUNKING → EMBEDDING → WRITING → DONE | FAILED`; Ollama'ya 96'lık toplu istek; eski parçaları silme + yenileri yazma + kaynağı güncelleme tek transaction.
3. Arama: `KEYWORD` (FTS `turkish`), `VECTOR` (HNSW + `SET LOCAL` ile `hnsw.*`), `HYBRID` (tek SQL, RRF). Model koruması, isteğe bağlı EXPLAIN, vurgulama konumları, arama kaydı.
4. Başlangıç verisi: 37 çalışma alanı, 1.410 parça (Dalga Fiber 42 parça ≈ %2,98), açılışta arka planda gerçekten `bge-m3` ile embed edilir; idempotent ve Ollama kapalıysa sonraki açılışta tamamlanır.
5. Docker Compose: `postgres` + `backend`; Ollama Mac'te (`host.docker.internal`).
6. `ollama.md` backend bölümü yeni akışla yeniden yazılır (devops, D24).

Değişen mevcut parçalar (eski ad → yeni ad yok; sadece genişleme):
- `EmbeddingClient`: yeni metot `EmbeddingBatchResult embedAll(List<String> texts)`; `embed(String)` aynen kalır.
- `EmbeddingProperties`: yeni alan `@Positive int dimensions` ve metot `String modelTag()` (`model + "@" + dimensions`).
- `GlobalExceptionHandler`: `handleMaxUploadSizeExceededException` ve `handleHandlerMethodValidation` override'ları (D12, D13). Yeni kategori sınıfları `NotFoundException`, `ConflictException`, `UnsupportedMediaTypeException`.
- `OpenApiConfig.ERROR_CODES`: sözleşmedeki 20 değerlik liste (aynı sıra); `API_VERSION = "0.2.0"`.
- Var olan `@SpringBootTest` testleri artık veritabanı ister (tester ortak Testcontainers taban sınıfına geçirir).

Bilinçli sapmalar (TASK, `backend-conventions`'tan önce gelir): `SourceResponse`, `SearchResultResponse`, `SearchHitResponse` alanları TASK Kural 4 ve 20'ye göre (convention'daki örnek şekiller değil); `SearchHitResponse` ham `distance` taşır (Kural 20 açıkça istiyor). Liste endpoint'leri `sort` almaz, sıra sabittir (D17).

Uygulama sırası (tek teslim, bölünmüyor): migration + repository'ler → yükleme/içe alma → arama → başlangıç verisi → Docker → rehber.

Kullanıcının cevapları (kart onaylandı): S1=A (PDFBox + Awaitility eklenir), S2=B (proje isim kuralına göre tablo adları). "Soru cevaplarına göre değişenler" bölümü artık sadece kayıt içindir. Onaydan sonra kullanıcı veri erişimini JPA olarak belirledi (Düzeltme turu 1).

### Migration'lar (`src/main/resources/db/migration`)
Adlandırma `postgres-patterns`'e göre. Hepsi yeni boş tablo; index'ler aynı dosyada, `CONCURRENTLY` yok.
- `V1__enable_vector_extension.sql`: `CREATE EXTENSION IF NOT EXISTS vector;`

- `V3__create_sources_table.sql`: `CREATE SEQUENCE sources_id_seq START WITH 10001 INCREMENT BY 1`; `sources(id bigint PRIMARY KEY, workspace_id` bigint NOT NULL FK → workspaces, name text NOT NULL, kind text NOT NULL, version text NULL, file_name text NULL, status text NOT NULL, chunk_count integer NOT NULL DEFAULT 0, synced_at timestamptz NULL, created_at timestamptz NOT NULL DEFAULT now())`; `ck_sources_name` (2-80), `ck_sources_kind IN ('WEB_CRAWL','PDF','MARKDOWN','CSV','TICKET_EXPORT')`, `ck_sources_status IN ('INGESTING','READY','FAILED')`, `ck_sources_version CHECK (version IS NULL OR char_length(version) BETWEEN 1 AND 40)`; `idx_sources_workspace_id (workspace_id)`; `uk_sources_workspace_id_name (workspace_id, lower(name))` unique; `ALTER SEQUENCE sources_id_seq OWNED BY sources.id` (testlerdeki `TRUNCATE ... RESTART IDENTITY` sequence'i de 10001'e döndürür).
- `V4__create_chunks_table.sql`: `CREATE SEQUENCE chunks_id_seq START WITH 1 INCREMENT BY 50` (+ `OWNED BY chunks.id`); `chunks(id bigint PRIMARY KEY, workspace_id bigint NOT NULL FK, source_id bigint NOT NULL FK → sources ON DELETE CASCADE, chunk_no integer NOT NULL CHECK (chunk_no >= 0), heading text NULL, content text NOT NULL CHECK (char_length(content) > 0), token_count integer NOT NULL, tsv tsvector GENERATED ALWAYS AS (to_tsvector('turkish'::regconfig, coalesce(heading, '') || ' ' || content)) STORED, embedding vector(1024) NOT NULL, embedding_model text NOT NULL, created_at timestamptz NOT NULL DEFAULT now())`. ### Arama SQL'i (ChunkSearchRepository)
Hepsi `ChunkSearchRepository`'de `@Query(nativeQuery = true)`; `ChunkRetrievalService`'in `@Transactional(readOnly = true)` metodunda `applySearchSettings` ile aynı transaction'da çalışır. Sonuç kolonları `RetrievedHitView` alias'larıyla (çift tırnaklı camelCase). Bütün kollarda `WHERE workspace_id = :workspaceId`. Vektör parametresi `CAST(:queryEmbedding AS vector)`; sorgu `plainto_tsquery('turkish', :query)`.
- **Oturum ayarları** (aynı transaction, D3-D5): `set_config('hnsw.ef_search', efSearch, true)`, `set_config('hnsw.iterative_scan', 'off'|'relaxed_order', true)`, `set_config('hnsw.max_scan_tuples', maxScanTuples, true)`, `forceVectorIndex` ise `set_config('enable_sort', 'off', true)`.
- **Kelime CTE'si** `keyword`: `id`, `ts_rank_cd(tsv, query) AS keyword_score`, `ROW_NUMBER() OVER (ORDER BY ts_rank_cd(tsv, query) DESC, id) AS rank`; `WHERE workspace_id = ? AND tsv @@ query ORDER BY keyword_score DESC, id LIMIT :limit`.
- **Vektör CTE'leri**: `semantic AS MATERIALIZED (SELECT id, embedding <=> q AS distance FROM chunks WHERE workspace_id = ? ORDER BY embedding <=> q LIMIT :limit)`, `semantic_ranked AS (SELECT id, distance, ROW_NUMBER() OVER (ORDER BY distance, id) AS rank FROM semantic)`. `ORDER BY` ham `<=>` ifadesiyle (index kullanılsın).
- **Keyword modu**: `keyword` + `chunks`/`sources` join, `ORDER BY rank`.
- **Vector modu**: `semantic_ranked` + join, `ORDER BY rank`.
- **Hybrid**: iki kol tek SQL'de; `FULL OUTER JOIN keyword k ON s.id = k.id`; `rrf_score = COALESCE(1.0 / (:rrfK + s.rank), 0) + COALESCE(1.0 / (:rrfK + k.rank), 0)`; `ORDER BY rrf_score DESC, s.rank NULLS LAST, id LIMIT :limit`; her satırda `(SELECT count(*) FROM keyword)` ve `(SELECT count(*) FROM semantic)` (sonuç boşsa iki sayı da 0'dır).
- **EXPLAIN**: `EXPLAIN (ANALYZE, BUFFERS, COSTS OFF)` + vector modundaki `semantic` iç sorgusu (lab `explainSql`), aynı oturum ayarlarıyla ayrı read-only transaction; satırlar `"\n"` ile birleşik. Spring Data native `@Query` EXPLAIN'i ya da bind parametreleri kabul etmezse aynı transaction'da `EntityManager.createNativeQuery` kullanılır ve sadece bu sorguda backend'in ürettiği sayısal değerler (vektör literal'i, `workspaceId`, `limit`) SQL'e yazılabilir; kullanıcı metni asla.
- **Kökler**: `SELECT DISTINCT unnest(tsvector_to_array(to_tsvector('turkish', ?)))`; kelimeler: `SELECT w, unnest(tsvector_to_array(to_tsvector('turkish', w))) FROM unnest(string_to_array(?, ' ')) AS w` (kelimeler tek boşlukla birleşik gönderilir).
- PostgreSQL'in "text-search query doesn't contain lexemes" NOTICE'ı hata değildir; boş sonuç döner (G3).

## Açık sorular ve riskler
- **HNSW zorlaması (D4):** `enable_sort=off` PostgreSQL 18'de "disabled node" sayımıyla çalışır; planner yine de HNSW seçmezse I23 kırılır. O durumda backend-coder ek olarak `enable_seqscan=off` + `enable_bitmapscan=off` dener ve raporlar; çözüm yoksa lead'e mesaj.
- **Post-filter gerçek veride (D15):** Q4 gerçek bge-m3 vektörleriyle ölçülür. Vektör kolu 10 dönerse qa raporlar; düzeltme seed'e (T alanlarına) daha çok nakil parçası eklemektir (planner'a geri döner).
- **Sürüm doğrulaması:** `pgvector/pgvector:0.8.1-pg18`, `pdfbox 3.0.6`, `eclipse-temurin:26-*` etiketleri çalışırken doğrulanır; yoksa en yakın yama sürümü kullanılır ve raporda yazılır.
- **Ollama süresi:** 1.410 parçanın ilk embed'i Mac'te birkaç dakika sürebilir; backend bu sırada healthy'dir, aramalar kısmi veri görür. 96'lık grup 60 s read timeout'u aşarsa iş `EMBEDDING_UNAVAILABLE` olur; o durumda `embedding.read-timeout` artırılır (backend-coder raporlar).
- **Kısa aşamalar:** PARSING/CHUNKING milisaniyeler sürer; sorgulamada görünmeyebilir, loglarda görünür (sahte bekleme eklenmez).
- **EXPLAIN bind parametresi:** Spring Data native `@Query` / pgjdbc ile `EXPLAIN ANALYZE` parametreli çalışmazsa "Arama SQL'i"ndeki `EntityManager` istisnası uygulanır.
- **Hibernate `validate` tip eşleşmesi:** `text` kolonları `String`, `timestamptz` `Instant`, `vector(1024)` `@Array(length = 1024)` ile doğrulanır; Hibernate bir kolonu farklı tip beklerse (ör. `varchar`) backend-coder ilgili alana `@Column(columnDefinition = "text")` ekler, migration'ı değiştirmez. Sequence'lerin artış miktarı `allocationSize` ile aynı olmalı (`chunks_id_seq` 50, `sources_id_seq` 1 — `Source` sequence'i Hibernate generator'ı değil, `nextSourceId()` ile okunur).
- **hibernate-vector sürümü:** `hibernate-core` ile aynı sürüm olmalı; Boot BOM'u yönetmiyorsa `${hibernate.version}` kullanılır.
- **Native projection alias'ları:** PostgreSQL tırnaksız alias'ı küçük harfe çevirir; `RetrievedHitView` eşlemesi için alias'lar çift tırnaklı camelCase yazılır.
- Kapsam dışı not: `backend-conventions` `SourceResponse`/`SearchHitResponse` şekillerini ve "ham distance response'a konmaz" kuralını sabitliyor, `vector(1536)` örneği veriyor; bu task TASK'a göre farklı (skill metnini kullanıcı/lead günceller). `deployment/CLAUDE.md` "backend dışa açılmaz" diyor; bu task'ta frontend olmadığı için 8080 açılıyor.
